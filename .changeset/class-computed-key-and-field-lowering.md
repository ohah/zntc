클래스 computed 키와 필드 다운레벨의 결함을 한꺼번에 고쳤습니다 (#4723).

**크래시·파싱 불가**

- `--target=es2015`~`es2021` 에서 **static 필드가 있는 익명 클래스 식**(`f(class { static [k] = 1 })`)이 **컴파일러를 죽였습니다.**
- `--target=es5` 에서 generator 안 클래스의 computed 키에 `yield` 가 있으면 산출물이 파싱되지 않았습니다(키가 클래스 IIFE 라는 **새 함수** 안으로 들어감).
- es2015~es2021 에서도 필드가 있는 클래스의 메서드·접근자 키에 `yield` 가 있으면 같은 이유로 파싱되지 않았습니다.

**값이 틀림**

- 인스턴스 필드의 computed 키가 **인스턴스를 만들 때마다 재평가**됐습니다(`class { [f()] = 1 }` 에서 `f` 가 여러 번 호출). 키는 클래스 정의 시점에 한 번만 평가돼야 합니다.
- es5 에서 **generator 안의 클래스 선언이 모듈 최상위로 끌려 나가** 바깥 변수를 잃었습니다(yield 가 없어도 재현).
- async generator 안 클래스 키의 `await` 가 제대로 표시되지 않아 키가 `undefined` 가 됐습니다.
- `const X = class {…}` 를 낮추면 `X.name` 이 `"_Class"`/`"_a"`/`""` 가 되던 것을 선언 이름 `"X"` 로 지킵니다.

필드가 있고 computed 키가 있는 클래스는 이제 **모든 멤버의 키를 소스 순서대로 클래스 앞에서 한 번** 평가합니다.
