# SymbolId producer identity and final-name audit

이 문서는 [#6120](https://github.com/ohah/zntc/issues/6120)의 source-only audit 결과다. 상위 색인은 [SYMBOL_IDENTITY_PRODUCER_CENSUS.md](./SYMBOL_IDENTITY_PRODUCER_CENSUS.md), 전체 migration 상황은 [SYMBOL_IDENTITY_MIGRATION.md](./SYMBOL_IDENTITY_MIGRATION.md)에 있다.

## 기준과 결론

- 기준 main: `7346fc2cb48980257f9fc5a8625dc627eb7f0768` (PR #6122 병합 뒤).
- 색인: **112개 constructor call expression**, 70개 함수, 35개 파일. 이 가운데 **111개는 production 경로에서 도달**하고, `es2015_for_of.zig::makeVarDeclFromSpan`의 1개 call은 production caller가 없는 helper 안에만 있다.
- 분류: **112/112**, 미분류 0. 이 분모에서 semantic graph가 있는 지원 경로의 **누락된 exact SymbolId handoff는 0**으로 판정했다. 이는 전체 #4819 final-name 작업이 완료됐다는 뜻이 아니다.
- 다섯 fallback/delegation constructor call은 semantic-less spelling fallback이거나 이미 caller가 보유한 exact binding ID를 재사용하는 경로다. `lists.zig::buildVarDecl`은 owner/SID를 호출자가 반환된 binding NodeIndex에 붙이는 공통 생성기다. 이 caller handoff도 각각 대조했다.
- Worklet 직렬화 AST의 두 binding call은 bounded 분모에 포함된다. 이 payload는 outer module graph와 분리된 SemanticAnalyzer graph로 이름과 reference를 연결하며, payload 안에서는 identifier minification을 실행하지 않는다.

`SymbolId` 보유 여부와 final spelling의 선택 시점은 별도 축이다. 비-minify 출력은 producer가 선택한 spelling을 유지할 수 있고, standalone late-name path와 bundler post-graph path는 해당 기능을 허용하는 symbol만 exact ID로 이름을 선택한다. Dynamic-scope/eval 제약이나 graphless transformer에서는 안전한 early spelling을 쓴다. 공통 소비자는 [`Codegen.finalSymbolName`](../src/codegen/codegen.zig#L441), standalone override 선택은 [`buildStandaloneLateOutputNameOverrides`](../src/transpile.zig#L1212), bundler는 [`resolvePostGraphOutputHintNames`](../src/bundler/linker.zig#L3044) 뒤 rename/mangle을 수행한다.

이 결과는 112개 AST binding-constructor index에 한정된다. reference-only 예약, plugin/linker-owned output binding, 별도 serialized payload 경계, semantic-less 실행 자체를 빠진 exact ID로 세지 않았다. Name/span/scope 재검색과 resolver/collision 및 다른 producer family는 #6004, #6003, #5952, #5954 등 기존 이슈의 범위다.

## Static initializer immutable capture delta (2026-10-25)

`static_class_capture.zig::ensureCapture` adds one reachable binding-constructor call after the historical 112-callsite census. It creates the binding with `makeExactSyntheticBindingFromSpan`, declares its SID in the planned output owner, and stores the binding/SID/owner in a map keyed by the exact class binding NodeIndex. Active initializer frames retain the source class-self SID independently of nested class visits. Generated `this`, class-self reads, native class-self writes, and generated static-super receivers consume that exact capture identity before output reconciliation. Native output uses a block `const`; ES5 uses a `var` inside each class IIFE evaluation and retains the existing throwing class-self write target. The class-value initializer is also an exact read of the declaration/native or implementation/ES5 SID.

Native capture declarations enter `preserve_const_declaration_indices` at creation. Top-level var demotion, const-to-let syntax minification, and cycle codegen demotion must all preserve this readonly contract. `Ast.cloneForTransformer` copies the declaration-index list into independent storage when carrying an already-transformed AST forward. Ordinary source declarations remain eligible for their existing demotions. Unique staging spellings are keyed by class binding NodeIndex, so nested captures cannot share a spelling before final output naming; spelling never selects their identities.

A moved class initializer has a separate dynamic-environment limitation. Nontrivial direct eval can observe lexical `this`, the immutable class-self binding, or private environment without corresponding AST references. These new cases fail with **ZNTC1505**, rather than emitting target-incompatible native syntax or silently changing behavior. Native static field/block contexts remain supported when retained. Bounded numeric arithmetic eval without leading-zero integer literals and bare identifier reads that cannot denote class-self or strict `arguments` remain supported. Other literal/opaque eval is conservatively rejected when moved with a static initializer, including ordinary-function `this`/`arguments` and statements: those functions inherit class strictness, which is also lost by movement. The literal classifier is conservative and rejects compound expressions/statements or escaped source rather than acting as a complete eval interpreter. A lexically bound callee named `eval` is also checked: it may hold the builtin and still perform direct eval. A lexical SymbolId alone cannot prove the call ordinary. Calls under another reference name remain indirect. If emission retries a module already carrying an error-level diagnostic with this exact code and module path, it emits no code for that module and preserves the structured failure; unrelated errors/warnings do not authorize omission. A direct emitter call without that provenance fails explicitly. Existing ZNTC1503/1504 warning behavior is unchanged. Assign semantics and decorators can move an initializer even when the configured target otherwise supports its syntax.

This delta does not remove `semantic_edit.zig`'s general spelling/base-name fallback. The separate private-static arrow pending-exact lifecycle crash and inherited strictness of moved ordinary functions without eval also remain tracked follow-ups. Neither this producer migration nor ZNTC1505 proves completion of the full #4819 migration.
