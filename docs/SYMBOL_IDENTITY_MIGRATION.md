# #4819 심볼 identity 전환과 보정 경로 제거

[에픽 #4819](https://github.com/ohah/zntc/issues/4819)의 목표는 사용자 변수와 생성 변수가 변환 중 같은 identity를 유지하고, 출력 직전에 이름을 확정하는 것이다. 이 문서는 현재 보정 경로를 제거할 조건과 다음 작업 단위를 기록한다. 새로운 AST나 별도 심볼 시스템을 도입하는 계획은 아니다.

생성자 표의 조사 기준은 2026-10-04의 `6ca87b46`이며, 이후 구현 상태는 아래 작업 순서에 기록한다. 아래 표는 확인한 주요 이름 생성자 계열이며, 모든 호출 지점과 문법·옵션 조합의 전수 목록은 아니다. private-field/decorator/class-self, Flow 및 plugin/worklet/refresh/emotion/styled-components의 생성 경로 전수조사는 남아 있다. 원본 AST를 보존해야 하는 bundler/cache/HMR의 메모리 소유권은 [기존 ownership RFC](./RFC_TRANSFORMER_OWN_AST.md)와 구분한다. AST 복사 제거와 의미 분석 재실행 제거는 다른 작업이다.

## 생성과 출력의 계약

- 심볼 기반 변환 경로에서 binding을 만들 때 `SymbolId`와 소유 `ScopeId`를 함께 정한다. 같은 변수의 reference는 그 handle을 받아 연결한다. 속성 이름, label, 미해결 외부 이름은 binding과 구분한다.
- 생성 함수의 소유 스코프를 나중에 만들 수밖에 없는 경우, 정확한 binding/reference 노드와 예정된 owner를 가진 보류 handle을 전달한다. 소유권이 결정된 뒤 이름을 다시 검색해 변수를 고르는 경로는 제거 대상으로 기록한다.
- AST 이동·복사는 identity를 유지하고 reference scope, 선언, 읽기/쓰기 및 문장별 사용 정보를 함께 갱신한다. 이동 전후 parent가 달라질 수 있으므로 source scope와 출력 scope를 구분해 검증한다.
- `flags.declare` 행의 `scope_id`는 그 심볼의 선언 대상 scope를 기록한다. 값 참조 행의 사용 위치 scope와 구분하며, 선언 심볼이 그 scope의 자식에서도 보인다는 사실만으로 잘못된 선언 소유권을 허용하지 않는다.
- 최종 이름 결정은 비-minify 출력도 포함한다. 미해결 전역, direct `eval`/`with`, export/property 이름, 외부 runtime 계약을 먼저 보존·예약하고 모든 내부 이름 소비자가 같은 결과를 사용한다.
- 출력 별칭과 원본 함수·클래스의 `.name`은 별도 계약이다. alias 예약은 Unicode escape를 해석한 identifier StringValue로 비교하고, 이름 복원은 정확한 초기화 식 노드와 선언 SID에 연결한다. 같은 선언의 이름을 변환기와 codegen이 중복 복원하지 않는다.
- 의도적인 분석 생략 또는 저수준 Transformer의 `semantic_edit_enabled=false` 경로는 적용 범위를 별도로 기록한다. 해당 경로의 `null`을 심볼 기반 경로에서 누락을 허용하는 근거로 사용하지 않는다.

## 보정 경로별 제거 조건

| 제거 대상                                               | 제거 전에 필요한 증거                                                                                                                                                        |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 생성 후 이름/span/scope 검색                            | 해당 생성자 binding/reference가 생성 또는 명시적 owner 확정 시점에 같은 SID를 가진다. 생성 시 등록을 끊으면 테스트가 실패하며, 보정 코드를 제거한 정상 구현은 통과한다.      |
| `canRetainGraphForAuditedSyntaxSubset`의 해당 문법 조건 | 그 변환이 AST와 semantic 정보를 함께 갱신하고, 함께 실행되는 helper·plugin·minify 변환도 해당 계약을 지킨다. 허용 조건만 바꿔 통과한 테스트는 제거 근거가 아니다.            |
| 재분석과 rename handoff                                 | 모든 적용 경로에서 SID, reference/statement 사용 정보, import/export, tree shaking 및 cache 재사용 정보가 변환 후에도 유효하다. 재분석 경로를 실제로 제거한 상태로 검증한다. |
| codegen 이름 치환·별도 allocator                        | 선언과 모든 참조가 심볼 또는 명시적인 외부 이름 계약으로 출력된다. 비-minify, identifier-minify, 전체 minify와 bundle/code splitting에서도 충돌·shadowing이 없다.            |
| `resolveSyntheticName`·`collidesWithUserSymbol`         | 위 생성자 이관과 최종 이름 결정이 끝나고, 미해결 전역 및 동적 스코프 예약을 포함한 실행 회귀가 통과한다. 검사기부터 삭제하지 않는다.                                         |

## 합의한 작업 순서

1. **source scope-parent 검사 연결 완료:** [PR #5057](https://github.com/ohah/zntc/pull/5057)에서 source AST의 owner/parent 검사와 CLI 호출을 연결했다. source parent 오류와 namespace/Flow의 기존 owner 표현 차이를 구분한다. 변환 후 출력 scope 검사를 대체하지 않으며, 전체 심볼 전환 완료를 뜻하지 않는다.
2. **매개변수·본문 binding 정적 분리:** [parameter_environment](../src/transformer/parameter_environment.zig)가 기본값·계산된 구조분해 key의 외부 참조와 충돌하는 본문 `var`·함수·`let`·`const`·클래스 선언을 기존 rename table에 연결한다. analyzer가 같은 SID로 합친 비단순 매개변수와 본문 `var`도, 매개변수 초기화 식에서 그 binding을 참조할 때 별도 SID로 나눈다. parameter reference를 새 SID로 옮기고, 매개변수 초기화가 끝난 뒤 본문 `var`에 초기값을 복사한다. closure가 가진 매개변수 값과 본문 변수를 분리하며, 계산된 key·구조분해 shorthand, parameter TDZ, 원본 함수 이름, 별칭 충돌을 실행과 exact graph로 검사한다. 이는 ES5 정적 변환 경로의 제한된 분리이며, 전체 parameter/body scope model을 구현한 것은 아니다.
3. **구조분해 매개변수 temp 생성 시 SID/scope 소유 강제:** [PR #5059](https://github.com/ohah/zntc/pull/5059)에서 ES5 parameter lowering이 활성 함수 scope에 temp를 생성하고 즉시 SID와 exact span map을 기록하도록 한다. semantic editing을 사용하지 않는 저수준 Transformer 경로는 no-op으로 유지하고, owner node가 아직 붙지 않은 예약 생성 함수 scope도 허용한다. 네 곳의 사후 재등록 fallback을 제거하고 직접 identity 검사와 standalone/bundle 실행 비교를 추가한다.
4. 이후 위 표의 한 생성자 계열씩 생성부터 최종 출력까지 이관한다. 각 PR에는 바뀐 지원 범위, 삭제한 보정 코드, 남은 호출 지점, 음성 대조 및 실제 실행 결과를 기록한다. 이 문서의 항목도 같은 PR에서 갱신한다.

### 개별 생성자 이관 기록

- ES5 기본 파생 생성자의 `_newTarget`은 호출자가 예약한 생성자 함수 scope에 생성 시점부터 SymbolId를 등록하고, `__callSuper` 읽기 참조에 같은 ID를 직접 연결한다. 이 경로는 이름을 다시 찾아 등록하던 `trackDerivedConstructorLocalSymbols` 사후 추적을 사용하지 않는다.
- ES5 explicit derived constructor는 body 방문 전에 `_newTarget` handle을 선언하고, `super()` 변환이 그 SymbolId를 직접 사용한다. body 후처리는 동일 binding 노드를 선언부에 넣는다. constructor body의 lexical `new.target` capture도 같은 handle을 쓰므로 중복 `_newTarget` 선언을 만들지 않는다. 직접·arrow `super()` scope와 parameter-default `new.target` 실행을 확인한다. parameter wrapper의 자체 binding은 별도 producer다.
- ES5/RN native-parameter arrow factory는 source arrow owner를 따라가며 생성한 `_newTarget` 참조 노드 handle을 보류한다. 함수 경계를 지날 때 owner도 capture frame과 함께 초기화·복원한다. 각 factory parameter SID가 준비되면 자기 owner의 참조와 중첩 factory의 capture argument를 직접 연결하고, 최종 output-scope walk에서만 사용 위치 ScopeId를 확정한다. 이 producer는 이름·scope 재검색을 하던 `trackGeneratedLocalSymbols` 경로를 쓰지 않는다. 사용자 `_newTarget` 매개변수 충돌, 중첩 arrow와 함수, retained class constructor의 pre-reanalysis graph를 검사한다.
- ES5 class getter/setter의 `_this`·`_arguments` capture는 `visitMethodBodyWithParams`가 선언 생성 시 frame/kind handle에 연결한다. accessor function expression 전체를 이름으로 다시 훑던 `trackThisArgumentsCaptureSymbols` 호출은 이 producer에서 제거한다. source accessor의 exact graph와 bundle/transpile-only 실행을 검사한다.
- ES5 prototype class method의 `_this`·`_arguments` capture는 ordinary body 방문과 `lowerAsyncOrGeneratorMethod`의 합성 함수 방문에서 생성 시 exact handle에 연결한다. `buildPrototypeAssignment`의 최종 function expression 이름 재검색을 제거하고 ordinary/prelowered async 경로의 exact graph와 bundle·transpile-only 실행을 검사한다.
- class async-generator의 mixed-capability fallback에서 `buildWrappedFunc`가 넣는 `_this`·`_arguments`도 `fillThisArgumentsCaptures`가 생성 시 exact handle로 연결한다. wrapper 전체를 다시 훑던 `trackThisArgumentsCaptureSymbols` 호출을 제거한다. `async_generator`는 유지하고 async/ generator는 낮추는 내부 capability 조합의 exact graph를 검사하며, 공개 ES5 async/generator 실행 회귀도 유지한다.
- `lowerAsyncFunction`의 `_this`·`_arguments` capture는 `fillThisArgumentsCaptures`가 alias 선언 생성 시 exact handle에 연결한다. 함수 전체 이름 재검색을 제거하고 async는 낮추되 generator는 유지하고 nested arrow는 낮추는 mixed-capability exact graph를 검사한다. 공개 ES2015 bundle/transpile-only는 generator-preserving wrapper의 런타임을, ES5 사례는 별도의 async-to-state-machine fallback을 검사한다.
- `lowerAsyncToStateMachine`의 `_this`·`_arguments` capture도 `fillThisArgumentsCaptures`가 생성 시 exact handle에 연결한다. 변환된 wrapper 전체 이름 재검색을 제거하고 exact graph에서 사용자 `_this` / `_arguments` 이름 충돌을 검사한다. ES5 bundle/transpile-only 런타임 케이스는 이 async-to-state-machine 경로를 덮는다.
- `lowerAsyncGeneratorToStateMachine`의 outer wrapper capture도 `fillThisArgumentsCaptures`가 alias 선언 생성 시 exact handle에 연결한다. wrapper 전체 이름 재검색을 제거하고 async-generator function의 parameter capture exact graph와 ES2017 bundle/transpile-only 런타임을 검사한다.
- 일반 `lowerGeneratorFunction` wrapper capture는 `fillThisArgumentsCaptures`에서 생성 시 exact handle에 연결한다. wrapper 전체 이름 재검색과 output owner를 기다렸다가 이름으로 다시 묶던 deferred-capture 표를 제거한다. 추출된 per-iteration generator의 source-frame capture exact graph 및 ES5 bundle/transpile-only closure 실행을 검사한다.
- 추출된 private method의 `_this`·`_arguments` alias도 `fillThisArgumentsCaptures`가 frame/kind handle로 직접 바인딩한다. `buildStandaloneFunc`에서는 이 두 이름을 다시 찾던 보정만 제거하고, output body 완성 뒤 소유 scope를 정해야 하는 임시 변수 추적은 유지한다. 중첩 arrow·같은 이름의 지역 변수 exact graph와 ES5 bundle 실행을 검사한다.
- 일반 function declaration의 `_this`·`_arguments` alias도 선언 생성 시 capture frame/kind handle을 등록하므로, `visitFunction` 뒤의 이름 기반 spec에서 제외한다. 완성된 output body에서 scope를 정해야 하는 temp completion은 유지하고, 같은 이름의 지역 변수 exact graph와 ES5 bundle 실행으로 확인한다.
- Stage 3 decorator가 만드는 `_metadata` binding과 class/member context 및 `Symbol.metadata` 접근 reference는 exact NodeIndex 목록으로 보유한다. static block의 최종 scope가 정해진 뒤 같은 SymbolId를 직접 붙여 metadata spec의 이름/span 재탐색을 제거하고, decorator와 바깥 `_metadata` 충돌 exact graph 및 ES5 실행으로 검사한다.
- Stage 3 class decorator의 `_classDecorators` binding과 `__esDecorate` 인자는 생성 시 exact NodeIndex로 보유하고, class decorator wrapper IIFE scope가 정해진 뒤 직접 연결한다. 같은 이름의 바깥 binding과 충돌하는 ES5 실행 및 nested class/member decorator exact graph를 검사하며, 다른 Stage 3 지역 변수 spec은 아직 유지한다.

- semantic completion이 찾은 generated function name은 exact name `NodeIndex`에 함수 표현식의 내부 scope 또는 선언 부모 scope를 지정해 직접 등록한다. function-name spec을 이름/span으로 다시 해결하는 호출을 제거하고, 합성 함수 이름의 owner scope와 등록 누락 mutation을 별도 검사한다.
- 일반 var temp hoister는 선언 binding을 만들 때 `bindHoistedTemp`로 owner `ScopeId`와 보류 reference를 직접 연결한다. 이 계약을 확인한 뒤 program-level temp spec pass와 `completeGeneratedStateSymbols` 안의 AST-wide generated-temp 수집/fallback 호출을 제거했다. scanner 둘을 끈 상태에서 전체 Zig 테스트와 exact oracle gate가 통과했고, hoister의 직접 등록을 끊는 mutation은 exact SymbolId 회귀에서 실패했다.
- 원본 function declaration의 hoisted temp도 `hoistTempVarsInOriginalFunction`이 실제 function `ScopeId`를 넘겨 같은 `bindHoistedTemp` 경로에서 생성 시점에 연결한다. declaration 방문 뒤의 GeneratedLocalSpec 수집/scanner를 제거했다. function/top-level nullish temp exact 회귀는 Debug/ReleaseFast와 전체 테스트에서 통과하고, function-scope 직접 등록을 끊는 mutation은 생성 심볼 4개 중 2개만 남겨 실패한다.
- `buildStandaloneFunc`가 추출하는 private method의 temp도 원본 method owner에서 exact function `ScopeId`를 복구한 뒤 `hoistTempVarsInOriginalFunction`/`bindHoistedTemp`로 직접 연결한다. 해당 helper의 GeneratedLocalSpec 수집/scanner와 더 이상 호출되지 않는 `appendGeneratedTempSpecs`를 제거했다. static private accessor/method exact-reference 회귀는 ES5/ES2015에서 통과했고, 직접 function-scope 등록을 끊는 mutation은 pending temp reference 6개를 남겨 실패한다.
- async-generator for-await가 제자리 변환 중 만드는 temp는 inner function var scope에 생성 즉시 등록하고 exact SymbolId를 각 참조에 연결한다. `es2017.zig`의 후처리 scanner 및 `GeneratedLocalSpec` 기반 generic scanner를 제거했다. 기존 전체 Zig suite에서 관측한 async-generator 변환 19회는 scanner 경계의 `generator_temp_var_spans`가 비어 있었고, 추가한 nested-generator 회귀는 바깥 generator의 state temp 9개가 살아 있는 경계를 재현한다. 양쪽 fixture에서 생성자 등록을 끊는 mutation은 각각 `missing_binding`과 `unclassified`로 exact coverage에 잡힌다. 제거 후 `zig build test`, exact oracle 90 tests/7,721 assertions, nested-generator Debug/ReleaseFast 회귀가 통과했다.
- Stage 3 멤버별 decorator 배열 이름을 중복 없이 배정하고 binding, assignment write, `__esDecorate` read를 exact NodeIndex/SymbolId로 연결한다. 같은 이름의 static/instance 멤버와 바깥 동명 변수 충돌에서 배열이 섞이지 않는 ES5 실행을 검사한다.
- Stage 3 private method descriptor binding, `__esDecorate` assignment write, generated private getter read를 exact NodeIndex/SymbolId로 연결한다. descriptor 선언은 일반 generated-local scanner에서 제외하고, instance/static scope graph와 바깥 동명 변수 충돌 runtime 실행을 검사한다.
- 합성 class auto-accessor setter의 `value` parameter/reference는 생성 시점의 두 NodeIndex를 `AccessorInfo`까지 전달한다. 최종 함수 ScopeId가 정해지는 `buildAccessorFunc`에서 그 exact handle을 직접 등록해, 함수 전체를 이름/span으로 훑던 `trackGeneratedLocalSymbols` 경로를 제거한다. Flow auto-accessor fixture의 바깥 `value` 충돌과 exact gate 전체 타깃, ES5 실행이 이 경계를 검사한다.
- 보류 중인 runtime-helper reference는 생성 당시 `current_scope`가 아니라 최종 출력 AST에서 확인한 owner `ScopeId`를 사용한다. `bindOutputScopesAndReferences`가 노드를 방문할 때 정확한 출력 scope로 보류 기록을 갱신하고, import/preamble SID를 연결하기 전에 적용한다. exact audit는 helper marker가 있는 참조도 알려진 출력 owner에서 `reference_scope_mismatch` 검사를 건너뛰지 않는다. ES5 `using`의 생성 try/catch/finally 블록에서 helper scope가 바깥 function scope에 남던 결함을 전체 Zig 테스트와 oracle fixture × target gate로 검사한다.
- styled-components CSS prop의 template/object forwarding이 만드는 `p => p._cssN` callback은 생성 시 function `ScopeId`, 매개변수 `SymbolId`, 모든 `p` read를 직접 연결한다. callback이 원본 JSX 위치의 함수 안에서 만들어져도 `_styled_N` 선언과 함께 program scope로 이동하는 사례를 exact graph 회귀로 확인하며, 원본 함수의 동명 `p`는 별도 SymbolId로 유지한다. 이는 이 CSS prop producer의 재분석 의존성을 제거한다. plugin/worklet/refresh/emotion/styled-components 전체 생성자 조사는 계속 남아 있다.
- React Native Worklets의 `__workletClass` factory 경로는 mutable factory `var`와 재구성 class의 immutable self-name을 각각 생성 시점의 `SymbolId`·owner `ScopeId`로 등록한다. factory 함수 반환·wrapper 호출·외부 class read와 재구성 class의 self reference를 정확히 연결하며, factory body의 class self reference는 AST 복제본으로 분리해 원본 parser reference를 바꾸지 않는다. 중첩 arrow, 같은 이름을 가리는 named function parameter, instance/static field initializer, static block, 빈 클래스의 ES5/ES2022 strict graph를 확인한다. non-computed field key는 closure 변수로 오인하지 않고 computed field key expression은 실제 외부 closure로 보존한다. 참조 복제·class-self map·factory 반환 reference·field-key closure 분류를 각각 끊는 hostile mutation은 exact gate에서 실패했다. 전체 plugin/worklet/refresh/emotion/styled-components 생성자 전수조사는 남아 있고 #4819는 열린 상태다.
- Namespace/enum IIFE 출력은 의미 분석의 owner map이 전달된 경우 생성 parameter의 exact `SymbolId`를 요구하고, 해당 row가 빠지면 text fallback 대신 명시적 codegen 오류를 낸다. namespace export prefix와 IIFE 이름은 동일 SID에서 읽는다. enum 출력은 `finishSemanticEdit`가 변환된 enum node의 owner remap을 반영한 뒤 그 SID를 조회한다. 가상 enum member도 owner SID 누락·범위 오류·잘못된 종류를 원문 이름으로 복구하지 않는다. 유효한 enum SID와 같은 이름의 멤버(`enum Self { Self = 1 }`), `E.A`와 충돌하는 바깥 `A`, owner 손상 mutation, 무분석 경로의 충돌 안전 text fallback을 검사한다. #5107의 namespace missing-owner 회귀와 가드 제거 mutation, enum missing-owner mutation으로 semantic/low-level 경계를 확인한다.
- ES5 class field와 computed member key prehoist는 `lowerClassWithPrehoistedKeys`의 `_a` write/read 및 static computed field의 `_b` IIFE memo binding/read를 생성 시 exact `SymbolId`·`ScopeId`로 연결한다. 바깥 temp sweep은 IIFE가 소유하는 memo temp를 소비해 중복 binding을 막는다. class declaration/expression, static/instance field, computed method/accessor, nested function, `_a` 충돌을 exact graph로 검사하고 직접 등록·IIFE binding 연결을 끊는 hostile mutation을 각각 확인했다 ([PR #5105](https://github.com/ohah/zntc/pull/5105)).
- 분석된 anonymous `export default` facade는 `binding_scanner`가 이름으로 `_default`를 찾지 않고 exact `export_default_declaration` node의 analyzer `SymbolId`를 연결한다. 같은 scope에 source `_default`가 있을 때 facade를 잘못 선택하지 않으며, `export default _default`는 정규 source binding으로 유지한다. facade node/SID 누락과 다른 source SID를 전달하는 mutation은 명시적으로 실패한다.
- 일반 `.local` export (`export` declaration, `export { local as public }`, `export default local`)도 parser scan과 AST rescan에서 exact local NodeIndex를 보유하고 analyzer `symbol_ids`로 연결한다. semantic map이 있는 경로에서 해당 node/SID가 빠졌을 때 scope-map 이름 fallback을 사용하지 않으며, unresolved global의 `null` SID는 invalid semantic ref로 남긴다. scope map을 다른 binding으로 오염하는 hostile regression, exact node/SID 누락 및 잘못된 SID 테스트가 이 경계를 검사한다. semantic map이 없는 저수준 호출의 기존 scope-name fallback은 별도 정리 대상으로 남긴다.
- PR #5121은 ES2015/ES2017 class computed-key prehoist의 generated temp 읽기와 define-semantics static field key의 최종 helper 인자를 exact SID/ScopeId에 연결했다. fixture × target exact matrix의 `missing_binding`과 `unclassified_reference`는 모두 0이다. 재분석·외부 이름 생성자·최종 naming 작업은 계속 남아 있다.
- anonymous private class expression의 `wrapClassExprInIIFE`는 wrapper 안의 class 선언 이름을 일반 temp hoister에 남겨 바깥 `var` 후보까지 만들고, wrapper class binding과 반환 reference를 직접 같은 SID에 연결하지 않았다. 이제 그 temp span을 소비하고 wrapper `ScopeId`에서 binding/reference를 직접 등록한다. class-transform 경로가 미리 이름을 만든 경우에도 동일한 owner를 전달하며, generated class-self map을 post-minify 검사에 넘긴다. derived class + TS parameter property + private/instance field의 ES2015/ES2017/ES2021 identifier-minify 회귀에서 exact 및 post-minify 누락·불일치가 0이고 실행 결과가 `5`다. static private assign-semantics와 static public-field downlevel 경로도 각각 실행 결과 `3`, `7` 및 exact/post-minify 오류 0이다. wrapper temp 소비를 제거한 mutation은 회귀 검사에서 중복 바깥 binding과 누락 identity를 만들고, assign-semantics static-private class-self 등록을 제거한 mutation은 기대한 map 항목이 1개에서 0개가 되어 실패한다. 이 구체 경로는 해결됐지만 private-field/decorator/class-self 생성자 전체 조사는 남아 있다.

### 매개변수 수정 후 남은 경계

- 본문 lexical 선언 자체의 ES5 TDZ 보존은 남아 있다. 예를 들어 `let x = 4`보다 앞에서 본문의 `x`를 읽으면 원본은 `ReferenceError`지만 현재 출력은 `undefined`를 읽을 수 있다. 매개변수가 외부 `x`를 읽도록 고친 것과 본문 TDZ 구현 완료를 구분한다.
- direct `eval`/`with`가 있는 동적 스코프는 정적 rename 대상에서 제외한다. source의 중복 함수 선언·TypeScript overload가 남기는 과거 심볼 행과 일부 재분석 진단도 별도 정리 대상이다. 실제 AST binding이 없는 행을 이번 rename으로 새 synthetic binding으로 만들지는 않는다.
- 이름 복원은 기존 `__name` helper를 사용한다. helper는 모듈 본문 실행 전에 내장 property-definition 함수를 보관하며, 모듈 시작 시 표준 intrinsic을 가정한다. standalone 출력은 hashbang·directive 뒤에서 helper를 writer로 출력해 실행 모드와 소스맵 위치를 유지한다.
- 생성자 전수 이관, 통합된 최종 이름 결정과 재분석 제거는 아직 완료하지 않았다. 구조분해 매개변수 생성 계약은 이 문서의 세 번째 작업 범위이며, 나머지 생성자 계열의 소유권 완성을 뜻하지 않는다.

## 검증과 완료 보고

- 구조 검사는 AST, SID, reference, scope owner/map의 일관성을 검사한다. `clean=1`만으로 원본 프로그램과 같은 의미라고 판정하지 않는다.
- 실행 검사는 원본을 실행 가능한 엔진에서 실행한 결과와 변환 출력을 비교한다. shadowing, closure, 평가 순서·횟수, 읽기/쓰기, direct `eval` 및 외부 이름 충돌을 포함한다.
- 적용된 변경에 따라 standalone/bundle, native/downlevel target, 기본 출력/identifier-minify/전체 minify를 비교한다. code splitting, JSX, helper, plugin/cache 경계는 해당 생성자를 이관할 때 포함한다.
- mutation은 생성 시 등록·reference 연결·scope 관계·검사 호출을 끊었을 때 실패하는지 확인한다. `retained`/`reanalyzed` 선택만 틀리게 만드는 mutation은 경계 정책 검사이며 런타임 의미 보존 증거와 구분한다.
- 테스트 함수 수, assertion 수, fixture × target 실행 수와 남은 구현 경계 수를 서로 환산하지 않는다. 각 작업은 실제로 삭제한 보정 경로와 아직 남은 범위로 보고한다.
- 이 문서 작성이나 일부 생성자의 이관만으로 #4819를 닫지 않는다. 최종 이름 결정과 재분석 제거를 포함한 에픽 종료 조건은 계속 유효하다.
